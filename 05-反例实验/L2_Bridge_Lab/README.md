# 单车道桥的四个反例实验

这四个练习分别回答三个问题：守卫漏掉了什么边界、一个绿灯承诺怎样失效，以及为什么所有安全条件成立时车辆仍可能没有进展。各机器均可独立初始化，使用本目录自己的上下文。完整精化链在 [L2_Bridge](../../03-Rodin工程/L2_Bridge/)，课程页码及建模步骤见[第二讲](../../02-课程讲义/02-单车道桥.md)。

**打开方式。** 在 Rodin 选择 File → Import → General → Existing Projects into Workspace，把本目录或上级目录设为根目录，勾选 `L2_Bridge_Lab`。保存、构建后打开相应机器的 Proof Obligations。有 ProB 时可载入该机器，给 d 取下述具体值，执行 INITIALISATION，再按事件顺序点选。各实验留下了预期无法证明的目标。下面五条轨迹已根据工程文件逐步核对守卫和动作。

| 机器 | 课件 PDF 页 | 现象 | 对应的正式机 |
|---|---|---|---|
| Lab0_Unguarded | 34–71 | 出车可得到负数，进车可超过容量 | M0_Capacity |
| Lab1_TwoGreens | 171–178、186–198、223 | 只开本端的灯，可能出现双绿 | M2_Lights 的两个换灯事件 |

## 1 总量模型没有守卫

取 `d=1`。第一条轨迹在初态执行 `ML_in`，得到 `n=−1`，违反 `count_natural`。第二条从重新初始化开始，执行 `ML_out → ML_out`，得到 `n=2`，违反 `capacity`。分别打开 `ML_in/count_natural/INV`、`ML_out/capacity/INV`，会看到无法从旧的不变式推出 `n−1∈ℕ` 或 `n+1≤d`。课件第 34 页就给了这两个没有守卫的动作。这里预先给定正容量，以单独观察守卫遗漏。修复时对 `ML_in` 加 `0<n`，对 `ML_out` 加 `n<d`。

## 2 只把本侧灯设为绿

取 `d=2`，依次执行 `ML_tl_green → ML_out1 → IL_in → IL_tl_green`。最后一次切灯前状态为 `(a,b,c)=(0,1,0)`、大陆绿、岛端红。岛端可以开绿，动作却没有把大陆灯关红，两个灯同时变绿。打开 `IL_tl_green/one_red/INV` 查看这一冲突。虽尚未有车迎面对驶，两端已同时获准上桥。

两条只开本侧灯的动作来自第 176 页。实验将第 196 页补出的互斥性质直接写入机器，并保留正确的边界分支，以便单独重放该问题。这是教学用组合。修复时，每个换灯事件同时把另一侧设为红，见正式机 `ML_tl_green`、`IL_tl_green`。

## 3 用掉最后的车位还显示绿灯

取 `d=1`，执行 `ML_tl_green → ML_out`。动作后 `a=1,b=c=0`，大陆依然绿；`main_green_safe` 却要求 `a+b<d`。此刻车辆数恰好达到上限，但灯已经向下一辆车给出了错误承诺。查看 `ML_out/main_green_safe/INV`，在其目标中代入此次动作前的零状态，会得到假判断 `1<1`。若允许从违例状态继续放行，才会真正突破容量。

未分支的上桥动作见第 171、175 页；本实验保留两灯互斥，用来排除第 2 个实验的干扰。修复方法是大陆分成 `ML_out1` 和 `ML_out2`，后者在本次放行用完最后一个车位时同时关灯。岛端对称考虑岛内最后一辆车，见正式机 `IL_out1/2`。

## 4 安全状态中的无限换灯

取 `d=2`，先执行 `ML_tl_green → ML_out1 → IL_in`。此时 `(a,b,c)=(0,1,0)`，大陆绿、岛端红。执行 `IL_tl_green → ML_tl_green` 后，三个计数和两盏灯全部回到原状态。同一对动作可以再次执行，所有不变式都成立。这是一条无限内部执行，不是“没有任何事件可选”的死锁。

换灯策略与循环来自第 224–231 页。为让失败在 Rodin 中可见，本实验手动把两个换灯事件设为 Convergent 并试用 `a+b+c` 作变式。换灯不会改变车数，因而 `ML_tl_green/VAR` 和 `IL_tl_green/VAR` 的严格下降目标都不成立。上述回到原状态的循环进一步说明，原策略不存在每次换灯都严格下降的状态变式。正式机加入本端通行记录，在换灯前要求对侧已有车通过，使用 `ml_pass+il_pass` 作变式。对比课件第 232–237 页可核对每个标志的置位和清零。
