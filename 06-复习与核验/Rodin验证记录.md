# Rodin 工程构建与证明记录

本次使用 Rodin 3.10 正式版、Java 21、macOS Apple Silicon。从工程的 `.project`、`.bum`、`.buc` 建立新工作区，逐项核对静态检查文件和证明义务。基础工程 ZIP 另行解压，在空工作区读入随包的 `.bpr` 并全量重建。下表的证明记录已在 2026 年 11 月 19 日的全新工作区重新导入核验。

## 如何读这份记录

**构建结果。** 5 个正式工程的 35 个组件及反例工程的 6 个组件全部通过 Rodin 静态检查，所有静态组件的 accurate 标记为 true。6 个工程均无静态错误或警告。反例工程特意保留可以推翻的性质。

**已消解。** 逐一对照 Rodin 生成的义务名称和证明状态，只计入已消解的义务。核心版使用 Rodin 自带证明工具，进阶版还使用 Atelier B Provers。两份工程的模型与上下文相同，保存的证明树不同。空白工作区只导入源文件、忽略已附证明，或另选自动证明组合时，显示的数量可能不同。

**读到 0 项时。** 生成器可直接化简平凡目标。0 项表示这个组件没有需要另外证明的生成项，不能据此断言每条自然语言需求都已形式化。有限状态搜索和独立符号计算的数字另见各讲末尾。

## 复核时从哪一步开始

1. 在 Rodin 选择一个新工作区。用 **File → Import… → General → Existing Projects into Workspace** 导入工程包，等自动构建结束。
2. 先展开 L2_Bridge / M0_Capacity 的 Proof Obligations。读 ML_out/inv0_2/INV，把动作代入 n ≤ d。比较不同证明配置对同一个整数不等式所给的证明树。
3. 转到 M1_Bridge 或 M3_Sensors 的无死锁定理，查看各分支使用哪些守卫和不变式。若自动策略不能完成，结合第二讲的车数分类与传感器状态做分情况推理。
4. 实际修改模型时另开练习副本。一次修改可能使已有证明需重新检查，重新构建后以新的 Proof Obligations 状态为准。

Rodin 的验证对象是随包模型及其公理。课件截图中的证明数量、有限实例的状态总数与本表各有不同含义。例如 Press7 的一个具体实例可有 2,816 个可达状态，而它在当前精化层的生成义务数量可以是零。

## 扩写版的公式与 PDF 核对

正文的公式按课件、原生工程和推导过程核对。银行的函数定义域、转账在途记录，桥梁的逻辑与物理计数、收敛变式，压力机的命令与反馈、按钮记忆和联锁，是逐层检查的重点。讲义把同一公式的文字解释、反例、证明义务和实际组件联系起来。若用更简短的数学写法概括数行公式，正文同时说明它与原模型的对应关系。

从原生 XML 中抽取并分类，共有 1,255 个谓词、赋值或变式字段。其中正式模型有 1,120 个，反例模型有 135 个。正式工程的 35 个上下文与机器源文件，逐文件与进阶证明包比对一致，再从源与证明树建立新工作区，得到 486 项已消解义务。课件省略的初始化、扫描步骤和教学扩展在相应讲义中说明。

| 核对对象 | 本版检查方法 |
|---|---|
| 上下文、机器与事件公式 | 对照课件页码、原生 XML 的标签和含义，核对类型、量词范围、定义域、边界值与并行动作 |
| 推导与示例轨迹 | 检查每一步的使能条件、动作前后状态、不变式与抽象层投影；对新增细读段再交叉复核 |
| 原生工程的证明 | 全新工作区导入，检查静态组件的 accurate 属性和 486 项义务的已消解状态 |
| 数学字符的显示 | 使用包含 Event-B 字符的嵌入字体，补充逻辑符号字体；关闭会将 ASCII 输入串自动合成为别的符号的连字 |
| Markdown 与 PDF 的对应 | 同目录同名逐份导出，检查标题、章节书签、图片资源和本地链接 |
| PDF 公式的回读 | 从每份 PDF 提取文本，对照 Markdown 中的行内及代码块内容；忽略分页产生的空白后逐段匹配 |
| PDF 版面 | 渲染页面检查长公式、跨页表头、图注、表格宽度和页边界 |

操作手册保留键入形式，例如 `..`、`:=`、`<+`。讲义中的数学结果采用 `‥`、`≔` 等 Rodin 字符。PDF 中这两种写法各自按源文保留，便于读者同时核对“键盘上怎么打”和“模型里是什么”。
