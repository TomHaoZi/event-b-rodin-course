# 桥梁模型的四个分步证明练习

打开 `L2_Bridge`。若要查看以下各题完整的 Proof Tree，请在装有 Atelier B Provers 的独立工作区导入[进阶证明包](../07-进阶证明/README.md)。以下写法用来在 Proof Tree 中选择假设和分情况；同一个目标用不同策略可能得到形状不同的证明树。小写 a、b、c 表示控制器的逻辑计数，大写 A、B、C 表示实际车数。每道题先问所要证明的是“有一步可走”，还是“这一步走过去仍然安全”。

## 1　M2_Lights 的无死锁定理

**目标为 `thm2_dlf/THM`。** 八项析取对应八个非初始化事件的守卫。只需找出其中一个为真。

1. 若 `c>0`，大陆端可接收返回大陆的车辆。若 `a>0`，岛端可接收进岛的车辆。剩下 `a=c=0`。
2. 若大陆灯绿，`inv2_3` 给出 `a+b<d`。整数的离散性保证 `a+b+1<d` 或 `a+b+1=d`，相应的大陆进桥分支可用。若岛灯绿，`inv2_4` 给出 `b>0`。按 `b=1` 或 `b≠1` 选择岛端分支。
3. 剩下两灯都红。由 `inv2_8`、`inv2_9`，两侧 pass 标志均为 1。若 `b>0`，可开岛端绿灯。若 `b=0`，则 `a+b=0<d`，可开大陆端绿灯。

在 Rodin 中先展开定理，而后用相应事件的守卫核对每个分支。若忘记使用正容量公理，在最后的空桥空岛状态就会卡住。

## 2　M3_Sensors 中大陆车辆进桥后的单向性

**目标为 `ML_out_dep/inv3_33/INV`。** 这次车辆实际上桥会给 A 加 1。要保持 `A=0 ∨ C=0`，应集中证明对向实际车数 `C=0`。

1. 从事件守卫得大陆灯绿。`inv2_3` 给出 `c=0`，`inv2_5` 与红绿取值互斥给出岛灯红。
2. 若 `il_out_10=TRUE`，`inv3_16` 要求岛灯绿，矛盾。因此岛端没有尚待处理的出岛消息。
3. 对 `ml_in_10` 分情况。若为 TRUE，`inv3_31` 给出 `C=c−1=−1`，和 `inv3_7` 的 `C∈ℕ` 矛盾。若为 FALSE，`inv3_32` 直接给出 `C=c=0`。
4. 该事件只改变本次涉及的现场计数和消息，C 保持 0。于是更新后的 A 无论是多少，单向条件都成立。

## 3　M3_Sensors 中岛端车辆进桥后的单向性

**目标为 `IL_out_dep/inv3_33/INV`。** 现在 C 加 1，须推出对向实际车数 `A=0`。

1. 岛灯绿配合 `inv2_4`、`inv2_5`，得到 `a=0` 且大陆灯红。由 `inv3_15` 排除 `ml_out_10=TRUE`。
2. 若 `il_in_10=TRUE`，`inv3_23` 给出 `A=a−1=−1`，与 `inv3_5` 矛盾。只剩 `il_in_10=FALSE`。
3. 用 `inv3_24` 得 `A=a=0`，检查该事件不会改变 A，证明完成。

这两道 INV 的关键都在于把“对面逻辑计数为零”转换成“对面实际计数为零”。只看颜色与小写计数，目标中仍会留下一个没有解释的大写变量。

## 4　M3_Sensors 的无死锁定理

**目标为 `thm3_dlf/THM`。** 对长析取，可以假设所有事件都不可用，逐步找出矛盾。纸上先把 16 个守卫按消息处理、换灯和实际到达／离开分类。

1. 如果 `ml_out_10` 为 TRUE，大陆灯绿且 `a+b<d`，正常与最后车位两个处理分支必开一个。如果 `il_out_10` 为 TRUE，按 `b=1` 与否同样能选到一个处理分支。因此两条 out 消息都为 FALSE。
2. 如果 `ml_in_10` 为 TRUE，由 `il_out_10` 为 FALSE 和 `inv3_31` 得 `C=c−1`。实际车数非负，故 `c>0`，消息处理可执行。`il_in_10` 为 TRUE 时由 `inv3_23` 同理得 `a>0`。因此两条 in 消息也都为 FALSE。把四个标志代入差值不变式，得到 `A=a`、`B=b`、`C=c`。
3. 桥两端的出桥探头 `ML_IN_SR`、`IL_IN_SR` 若为 on，对应 dep 可执行。若为 off 且有对应方向的实际车，arr 可执行。于是“全都不能动”迫使两个探头都为 off，且 `A=C=0`，从而 `a=c=0`。
4. 大陆出发端的 `ML_OUT_SR` 若为 off，在没有待处理消息时可 arr，故只可能为 on。若大陆灯绿，则 dep 可执行，因此大陆灯红且 `ml_pass=1`。
5. 若 `b>0` 且岛灯红，`IL_tl_green` 可执行。若 `b>0` 且岛灯绿，此时 `B=b>0`，岛端出发探头为 off 时可以 arr，为 on 时可以 dep。于是只剩 `b=0`。
6. `b=0` 排除岛灯绿，因此岛灯红且 `il_pass=1`。此时 `a+b=0<d`、`c=0`，两侧均无待处理的 out 消息，大陆可以开绿灯。与所有事件都不可用的假设矛盾。

这个论证只需证明任一时刻存在一个使能事件。若问题改为“特定车辆何时通过”，还要描述等待车辆、调度选择及公平性。

## 5 从证明树追到模型中的一行

| 在 Proof Obligations 里打开 | 先把目标改写成纸上等式 | 第一条值得找的假设 |
|---|---|---|
| `M2_Lights` 的 `ML_out2/inv2_3/INV` | 放最后一个空位后，若大陆灯仍绿是否还有余量？具体动作已令本灯变红。 | 上下文的 `green≠red` 可使新蕴含式的前件为假。 |
| `M2_Lights` 的 `ML_tl_green/VAR` | 本端置 0，目标是新旧两个 pass 之和严格比较。 | 本端原来是红灯，由 `inv2_8` 得旧 `ml_pass=1`。 |
| `M3_Sensors` 的 `ML_out_dep/inv3_33/INV` | `A+1=0 ∨ C=0`，故应设法推出右支。 | 现场守卫“大陆绿”给 `c=0`；还要通过两条回程通道的消息把 c 转换成 C。 |
| `M3_Sensors` 的 `ML_out_dep/inv3_34/INV` | `A+1+B+C≤d`，动作前必须留有一个实际位置。 | `ML_OUT_SR=on` 要求 `ml_out_10=FALSE`，大陆绿要求 `a+b<d ∧ c=0`。 |

最后一条可在纸上做完整代入。如果用方括号把 TRUE 记为 1、FALSE 记为 0，则三个差值式相加为 `A+B+C=a+b+c+[ml_out_10]−[ml_in_10]`。记号只供算题，工程中的正式假设是十二条布尔分类公式。代入本事件守卫及其推得的 `c=0` 和 `ml_out_10=FALSE`，得到动作前 `A+B+C=a+b−[ml_in_10]≤a+b<d`。实际车辆数是整数，增加一辆仍有 `A+1+B+C≤d`。这一步把“有逻辑余量”转译成“物理余量足够”，可与第 2 题的“逻辑对向空”转译成“实际对向空”并排练习。

打开已结案的证明树时，可先在 Explorer 定位目标，切换 Proving 视图，选中包含目标的节点读取它的 Sequent。要练习自行选择假设，请使用不同项目名的副本，核对 Goal 中的变量大小写，再在 Hypotheses 找到前述条件。交互证明中某个分支呈现 `⊤` 往往表示相应结论已化简为真；在反证中以 `⊥` 为目标，则表示须从当前分支的假设真正导出矛盾。不要把两种符号的角色交换。
